Externalized CFD expertise, guided by simulation evidence.

EasyFoam externalizes OpenFOAM expertise into modular skills, references, schemas, and deterministic tools. A coding agent uses these resources to plan, construct, run, assess, and repair a CFD workflow.

Beyond a successful solver run

A simulation can finish successfully and still miss numerical or physical requirements. The accompanying paper studies this executability–acceptability gap and asks how CFD expertise can be reused and refined across agent implementations.

01

Execution completion

Did the prescribed workflow complete?

02

Numerical soundness

Does the solution meet the required numerical checks?

03

QoI satisfaction

Do the quantities of interest meet the task criteria?

Task acceptance requires all three dimensions to pass. Missing evidence is not a pass.

An evidence-driven dual-loop framework

Within a task, structured evidence guides construction and targeted repair. Across tasks, experience can inform reusable skill revisions.

From the framework to the library

In-task workflow

Plan → Write → Run → Postprocess

CaseSpec makes requirements explicit. Stage-scoped repair reopens the earliest affected stage and invalidates dependent completion claims, while retaining prior run records.

Across-task evolution

Experience → Candidate → Validation → Human decision

The paper studies candidate selection through paired evaluation. The released library provides reviewed, reversible updates: applying, retaining, and rolling back changes require explicit human instruction.

What is in the library?

Workflow

Plan, author, execute, diagnose, validate, and postprocess a case. Recoverable state and immutable run records preserve the evidence trail.

Evolution

Retain supported experience, propose a frozen patch, validate it, and request a human decision. Changes can be deferred, rejected, or rolled back.

Reference & tools

Read-only OpenFOAM and CFD knowledge, seven artifact schemas, and deterministic Python scripts for parsing, validation, execution, and state management.

Start with the library

Use Python 3.11 or 3.12, OpenFOAM Foundation v13, Git, and a coding agent with file and command execution capabilities. Windows runs OpenFOAM through WSL; Linux and WSL support native execution.

$env:EASYFOAM_OPENFOAM_BASHRC = "/opt/openfoam13/etc/bashrc"

Set the bashrc path to your actual OpenFOAM installation. On Windows, use the path visible inside WSL.
